## 关于毕业设计


这几天毕业设计工作才完全结束，论文提交，回家了，准备工作。 
5-27院级答辩，我们是22人一大组的，由三个指导老师指导的全部学生一起，每个学生都有一个主审阅老师。一般会问三个问题，且都由主审阅提出，其他老师不太会问，答辩时一个一个进去（但有些组不严，会很多人一起进入答辩），全程一般15-20分钟，如果老师了解你论文的方向，可能会问的深一点，如果老师一点都不懂，那他可能直接不会了。。。就过了。

## 注意事项：

### 论文：

一切以论文格式为主，把格式弄好比内容什么的都强。但论文一定要通顺

前面的摘要，最好分三段，不要出现“本系统，本论文，本xxx”

全篇最好不要弄太太太多代码，图片等，我知道有些人一半的内容都是代码和图片，会被批的

字数15000-20000就行，不要太多，除非特别牛的人。论文里一半的内容都最好是自己的东西，前面理论讲解什么的，最好都不要使劲抄。

### ppt 制作：

把自己做的东西着重讲解，什么封面，致谢，感谢，展望，老师没时间看的。我当时打开ppt，老师说直接讲第三章（如何设计的），然后巴拉巴拉一堆，就开始演示（有可能不会让你演示，直接提问），提问。

讲解落落大方，不要念ppt，不要全程低头，加以手势动作。及时记录老师提出的问题和建议。

### 其他：

其实我们写的东西，老师一眼就知道是自己做的还是买来的，不用各种担心。（其实我同学在答辩的前一个星期被导师训，说他做的一塌糊涂，然后当天就买了一个项目，答辩时照样通过，所以不必太担心）

老师的问题和其他的，可能会现场让你改代码；或者指出某个功能的代码位置在哪，现场写个sql语句。即使改不了，你可以说：老师，这个修改起来太复杂，需要1-2h，我下午或者明天给你看。老师一般会答应。

其实还有一个点，如果你的指导老师特别厉害，是个大拿，且你的主评审老师不太行，那你相对幸运一点，碍于面子和地位，主评审是不会提太难的问题，不会为难你的。但如果刚好相反，指导老师不太行，而主评审老师特别牛，那他提的问题可难可简单，没人敢反驳的，你导师也不敢说什么。

- 5-27 一辩是系里答辩，相对比二辩难，每个大组会选1-3个分数最低的去参加二辩，流程比较严谨。成绩会的当天出来，但不会公布。

- 6-12 二辩是院级答辩，应该不会再看程序的，上去直接投影论文，几个老师看你的论文格式，读你的论文。应该是都会过的（同学参加了，我没参加，具体不知道）

- 6-14 三辩校级，都是抽学号去参加校级答辩，一个院可能就5-10个人会被抽到（我没参加，具体不知道）

一般校级答辩之后就彻底没事了，把论文和材料交了，就 ok
